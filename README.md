# Ahmed Ali Ghori — 3D portfolio

A night rooftop world, modelled and lit in Blender, exported as glTF, and walked
through with the scroll wheel in the browser.

- **World**: one Blender scene — rooftop deck, glass studio, 154 procedural city
  buildings, four floating project panels, ~5.5k faces, procedurally generated
  facade and sky textures (no external assets).
- **Camera**: a ten-point path authored as empties inside Blender
  (`Path_01…Path_10`), exported in the glTF and sampled by `src/story.js`.
- **Content**: real — pulled from `github.com/AHMEDALIGHORI`; every project line
  and link comes from the repository description or its live deployment.

## Features

| Area | What it does |
|---|---|
| 3D world | Blender-built rooftop + city, glTF (`0.85 MB`), bloom, fog, ACES tone mapping |
| Scroll story | 9 chapters, damped camera on a Blender-authored path |
| Project panels | HTML cards projected onto 3D frames; hover highlights the frame, click opens the case study |
| Case studies | Full-screen sheet with live-site screenshot, metrics, highlights, stack, deep link `#/work/<id>` |
| Guided tour | ▶ button flies the camera through every chapter (~52 s), stops the moment you scroll |
| Night / dusk | ☾ button relights the whole scene (sky, fog, exposure, emissive strength) |
| Ambient sound | ◌ synthesises a rooftop hum with Web Audio — no audio file, no licence |
| Cursor light | a point light follows the pointer across the deck |
| Filters | stack chips filter the "more" list and dim non-matching panels |
| Live stats | GitHub API numbers with a 30-minute cache, baked values as fallback |
| Avatar | real GitHub profile photo, hidden automatically if unavailable |
| Experience | LinkedIn timeline component — renders only when `experience` has entries |
| Contact form | posts to a Formspree/Getform endpoint when configured; explains itself otherwise |
| Share card | `public/og.jpg` rendered in Blender at 1200×630, wired into OG/Twitter tags |
| Deep links | `?`–free hash routes so every project is shareable |
| Fallbacks | no WebGL → readable long-form page; no `backdrop-filter` → opaque panels; low fps → bloom off, DPR 1 |
| Quality | reduced-motion respected, keyboard focus states, ARIA on switches and dialogs |

## Run it

```bash
cd E:\portfolio-3d
pnpm install          # first time only
pnpm dev              # http://127.0.0.1:5180
```

Production build:

```bash
pnpm build            # -> dist/ (static, deploy anywhere)
pnpm preview          # serve the build on http://127.0.0.1:4180
```

`vite.config.js` sets `base: './'`, so `dist/` works from a subfolder, GitHub
Pages, Vercel or any static host.

## Rebuild the 3D world

The scene is generated by a script, not hand-modelled in a .blend you have to
maintain:

```bash
# inside Blender (Scripting tab, or via the Blender MCP tool)
runpy.run_path(r"E:\portfolio-3d\blender\build_world.py", run_name="__main__")

# social card, headless
blender -b blender/world.blend --python blender/render_og.py -- public/og.jpg
```

| Output | Purpose |
|---|---|
| `blender/world.blend` | editable scene, camera path, empties |
| `public/models/world.glb` | web-ready glTF, textures embedded (0.85 MB) |
| `public/textures/*.png` | generated facade / sky / street maps |
| `public/og.jpg` | social preview rendered from the same scene |

Change the palette, path points or panel positions in `build_world.py` and rerun;
the site picks up the new glb without code changes.

## Editing content

`src/content.js` is the single source of truth — profile, skills, featured
projects with case studies, the "more" list, filters and chapter windows.

- **Experience**: fill the `experience` array (period / role / org / note) and the
  About section renders a timeline. Empty array = section hidden, no placeholders.
- **Contact**: set `contact.endpoint` to a Formspree endpoint to enable real
  submissions. With no endpoint the form explains that and points at LinkedIn.
- **Stats**: `node scripts/update-stats.mjs` re-reads the GitHub API and rewrites
  the baked repository / deployment counts.

## Deploy

**Vercel** — import the repo; `vercel.json` already sets the build command,
output directory and long-lived cache headers for `/models`, `/work` and `/assets`.

**GitHub Pages** — push to `main`; `.github/workflows/deploy.yml` builds with pnpm
and publishes `dist/`.

Either way, keep the glb and the `work/` screenshots on the same origin so the
preload and cache headers apply.

## Verify

```bash
node scripts/shoot.mjs            # 13 screenshots: every chapter, case study, dusk, filter, mobile
node scripts/test-interaction.mjs # hover, panel click, case close, tour, light, sound
node scripts/debug.mjs            # card projection inspector for one scroll position
node scripts/capture-sites.mjs    # refresh public/work/*.jpg from the live sites
```

The screenshot pass loads the page in headless Edge with GPU enabled, waits for
`document.body.dataset.ready`, then captures each chapter and prints any console
errors. The interaction test drives real mouse events over CDP.

## Notes and limits

- **Blender 5.2.3 (portable) crashes on EEVEE** on this machine; use Cycles for
  renders. The web build is unaffected.
- **JPEG textures made the glb larger** (0.91 MB vs 0.85 MB) — the payload is
  mostly buffers, so PNG was kept. Serve with gzip/brotli at the edge.
- Panels are HTML cards positioned by projecting their glTF anchors, so text stays
  crisp and selectable while the frame lives in 3D.
- **LinkedIn blocks automated fetching** (HTTP 999). The site links to the profile
  and leaves the experience timeline empty until real text is supplied.
- Verified in Chromium (headless Edge, GPU) at 1600×900 and 390×844. Safari/iOS
  and low-end Android have not been tested on a device.
